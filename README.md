# 誕生日のパラドックス（birthday-paradox）

「教室に何人いれば、同じ誕生日のペアが50%の確率でいるか」——答えは23人。
信じられない人のために、**動かして・実際に試せる**ページ。
完全ブラウザ内動作（送信なし・外部ライブラリゼロ）。

▶ https://d-studylab.com/birthday-paradox/

---

## 中身

1. **人数スライダー**（2〜80人）— 動かすと確率が即変わる。身近な人数のチップつき
2. **1万部屋つくる** — その人数の部屋を1万個つくって誕生日をくじ引きし、理論値に寄ることを見せる。最初の200部屋は色つきの点で表示
3. **誤解の正体を並べる** — 「誰かと誰かが同じ」と「自分と同じ」を左右に並べ、ペアの数（253通り vs 22通り）まで出す
4. **グラフ** — 2〜80人の2本の曲線。50%の破線と、いま選んでいる人数の縦線
5. **身近な人数の表**

## なぜ23人で足りるのか（このページの主張）

少なく感じるのは、**「自分と同じ誕生日の人」を探していると思い込むから**。
実際に数えているのは**すべてのペア**で、23人なら 23×22÷2 = **253通り**ある。
自分がからむのは22通りだけなので、**11倍以上見ている**。

- 誰かと誰かが同じ（23人）… **50.7%**
- 自分と同じ（23人）… **6.1%**
- 「自分と同じ」が50%を超えるのに必要な人数… **253人**

## 計算の中身

全員バラバラの確率 `365/365 × 364/365 × …` を掛けて1から引く。
掛け算をそのまま回すと桁が飛ぶので**対数で足してから戻している**。

⚠ 365人でも数学的には1未満（全員バラバラの確率 ≒ 1.45e-157）だが、
倍精度では `1 - 1.45e-157` が 1 に丸まる。実装の誤りではなく浮動小数点の限界で、
テストにもその旨を書いてある。366人は鳩の巣原理で早期に1を返す。

## 前提（画面にも書いてある）

- **うるう年（2月29日）は扱わない。** 365日すべて同じ確率で生まれる前提
- 実際の出生日には季節の偏りがあり、**偏りがあると確率はさらに上がる**（同じ日に集まりやすくなるため）

## テスト

```
node birthday.test.js    # 30件
```

教科書的に知られている値と突き合わせている（23人=50.7% / 30人=70.6% / 50人=97.0% /
70人=99.9% / 99%を超えるのは57人 / 自分と同じが50%超えは253人）。
シミュレーションが2万部屋で理論値±1.5ポイントに入ることも検査。
